# v0.1 implementation plan — Rust language slice

Tracks the design at `docs/superpowers/specs/2026-05-01-rust-port-design.md`.
TDD throughout: tests precede implementation in each task. Each task ends with `cargo test` green and a commit.

## Phase 0 — Workspace skeleton

- [x] Create root `Cargo.toml` workspace with members: `dslp-core`, `dslp-base`, `dslp-engine`, `dslp-lang-rust`, `dslp-cli`
- [x] Each crate has its own `Cargo.toml` and `src/lib.rs` (or `main.rs` for cli) with a placeholder doc comment
- [x] `cargo build` succeeds at the empty-skeleton level
- [x] `.gitignore` covers `target/`, `.dslp/`

## Phase 1 — `dslp-core`

- [x] `Severity` enum (Low/Medium/High/Critical) with `weight() -> u32`
- [x] `Span { start: Position, end: Position }`, `Position { line, col }`
- [x] `Finding` struct (per design doc)
- [x] `Issue` struct (a Finding tracked across scans, with `first_seen`/`last_seen`/`resolved`)
- [x] `Score` struct (composite + per-detector subtotals)
- [x] `LanguagePlugin` trait
- [x] `ScanContext` struct (project root, config ref, output sink)
- [x] Tests: severity weights, fingerprint stability, struct serde roundtrip

## Phase 2 — `dslp-base`

- [x] `discover_files(root, plugin_extensions, excludes)` → `Vec<PathBuf>` using the `ignore` crate (gitignore-aware)
- [x] `Config` struct + TOML loader, with sensible defaults when file is absent
- [x] Tree-sitter wrapper: `parse(lang_id, source) -> Result<Tree>` with a per-language grammar registry
- [x] `ParsedFile { path, source, tree }` carrying everything detectors need
- [x] Tests: discovery respects gitignore, config loads with missing file, parser produces a Tree for trivial inputs

## Phase 3 — `dslp-lang-rust`

- [x] Implement `LanguagePlugin` for Rust
- [x] **Detector 1: `rust.file-size`** — flag files > threshold lines. Severity ramps with size.
- [x] **Detector 2: `rust.complexity`** — count cyclomatic branches per fn (`if`/`while`/`for`/`match-arm`/`?`/`&&`/`||`); flag at threshold. Also flag fns over length threshold.
- [x] **Detector 3: `rust.dead-pub`** — find `pub fn`/`pub struct`/`pub enum` whose name is not referenced elsewhere in the crate. Skip if `lib.rs`/`main.rs` re-exports it. Mark as Low severity given inherent imprecision.
- [x] Each detector has a positive test (fires when expected) and a negative test (doesn't fire when not expected)

## Phase 4 — `dslp-engine`

- [x] `Engine::scan(plugins, project_root)` orchestrates discovery → parse → plugin scan → finding aggregation
- [x] `score(findings, total_loc) -> Score` per the formula in design §3
- [x] State I/O: read/write `.dslp/state.json`, merge by fingerprint (new/existing/resolved)
- [x] `Engine::next(state) -> Option<Issue>` for the `next` command
- [x] Tests: scoring formula on synthetic inputs, state merge across two runs (new + resolved + persisted)

## Phase 5 — `dslp-cli`

- [x] `clap`-based arg parsing for `scan` and `next`
- [x] Output formatter (human-readable per design §4)
- [x] Exit codes: scan = 0 always, next = 0 when issue printed, 1 when nothing to do or no scan exists
- [x] Integration test: invoke `dslp scan` then `dslp next` against a fixture project, assert exit codes and output substrings

## Phase 6 — Dogfood + wrap

- [x] `cargo run -- scan --path .` against this very repo
- [x] `cargo run -- next` and verify the output is sensible
- [x] README at workspace root documenting install, usage, current limitations
- [x] Final commit + summary

## Non-goals (reserve, don't build)

- `--json` output, `resolve`, `suppress`, `plan`, `backlog`
- LLM intelligence
- Other languages
- Framework specs
- Anti-gaming / lenient-strict split
- Per-finding `--detail` view
